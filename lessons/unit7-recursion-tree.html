Recursion Tree

A Recursion Tree is a tree-like diagram that represents how a recursive function calls itself.

It helps us understand:

  • How recursive calls are generated.
  • The order in which functions are executed.
  • The number of recursive calls.
  • Time complexity analysis.

A recursion tree is one of the easiest ways to visualize recursion.

Why Do We Need a Recursion Tree?

Suppose we call:

factorial(5);

Instead of imagining many function calls, we can draw them as a tree.

A recursion tree makes it easier to:

  • Visualize recursive execution.
  • Count the number of function calls.
  • Analyze algorithm efficiency.

Example 1: Factorial

Recursive function:

int factorial(int n)
{
    if(n == 0)
        return 1;

    return n * factorial(n - 1);
}

Call:

factorial(5);

Recursion Tree

factorial(5)
      │
      ▼
factorial(4)
      │
      ▼
factorial(3)
      │
      ▼
factorial(2)
      │
      ▼
factorial(1)
      │
      ▼
factorial(0)

Notice that each function makes only one recursive call, so the recursion tree is actually a straight chain.

Returning Phase

Once the base case is reached:

factorial(0) = 1

↓

factorial(1) = 1 × 1 = 1

↓

factorial(2) = 2 × 1 = 2

↓

factorial(3) = 3 × 2 = 6

↓

factorial(4) = 4 × 6 = 24

↓

factorial(5) = 5 × 24 = 120

Example 2: Sum of N Numbers

int sum(int n)
{
    if(n == 0)
        return 0;

    return n + sum(n-1);
}

Call:

sum(4);

Recursion Tree:

sum(4)
  │
  ▼
sum(3)
  │
  ▼
sum(2)
  │
  ▼
sum(1)
  │
  ▼
sum(0)

Returning:

sum(0)=0

↓

sum(1)=1

↓

sum(2)=3

↓

sum(3)=6

↓

sum(4)=10

Again, only one recursive call is made each time.

Example 3: Fibonacci Recursion Tree

Recursive function:

int fib(int n)
{
    if(n <= 1)
        return n;

    return fib(n-1) + fib(n-2);
}

Call:

fib(5);

Recursion Tree:

                    fib(5)
                  /        \
             fib(4)       fib(3)
            /     \       /     \
        fib(3) fib(2) fib(2) fib(1)
        /   \    / \    / \
   fib(2) fib(1)1  0   1   0
    / \
   1   0

Observation

Look carefully.

fib(3)

is calculated multiple times.

Also,

fib(2)

is calculated several times.

This repeated computation makes recursive Fibonacci inefficient.

Number of Calls

For:

fib(5)

Calls made include:

fib(5)

fib(4)

fib(3)

fib(3)

fib(2)

fib(2)

fib(2)

fib(1)

fib(1)

fib(1)

fib(0)

fib(0)

fib(0)

Many calls are repeated.

Tree:

5

↓

4

↓

3

↓

2

↓

1

↓

0

Number of levels = n

Work per level = O(1)

Total Time:

O(n)

Sum of N Numbers

Exactly the same.

O(n)

Fibonacci

Tree branches into two recursive calls.

fib(n)

↓

fib(n-1)

↓

fib(n-2)

The number of nodes grows exponentially.

Time Complexity:

O(2ⁿ)

This is why the naive recursive Fibonacci algorithm is slow.

Merge Sort Recursion Tree

Array:

8 elements

Tree:

                8
             /     \
            4       4
          /  \    /   \
         2    2  2     2
        / \  / \/ \   / \
       1 1 1 1 1 1 1 1

Levels

Level 0 : 8

Level 1 : 4 + 4

Level 2 : 2 + 2 + 2 + 2

Level 3 : 1 + 1 + 1 + 1 + 1 + 1 + 1 + 1

Each level processes n elements.

Number of levels:

log₂ n

Total Time:

O(n log n)

Quick Sort (Best Case)

Best-case recursion tree:

             n
           /   \
        n/2   n/2
       / \     / \
    n/4 n/4 n/4 n/4

Levels:

log₂ n

Work per level:

n

Total:

O(n log n)

Quick Sort (Worst Case)

Worst case:

n

↓

n-1

↓

n-2

↓

n-3

Only one side contains elements.

Levels:

n

Work:

n + (n-1) + (n-2)...

=

O(n²)

Advantages of Recursion Tree

  • Easy to visualize recursion.
  • Helps understand recursive execution.
  • Useful for analyzing time complexity.
  • Shows repeated computations.
  • Helps optimize recursive algorithms.

Disadvantages

  • Large trees become difficult to draw.
  • Exponential trees consume a lot of space.
  • Complex for deeply nested recursive algorithms.

Common Algorithms Using Recursion Trees

  • Fibonacci
  • Merge Sort
  • Quick Sort
  • Binary Search
  • Tower of Hanoi
  • Divide and Conquer algorithms

Key Points to Remember

  • A Recursion Tree visually represents recursive function calls.
  • Each node represents a function call.
  • The tree grows until the base case is reached.
  • Linear recursion (e.g., Factorial) forms a chain of calls.
  • Binary recursion (e.g., Fibonacci) branches into two calls at each level.
  • Recursion trees are useful for understanding and analyzing recursive algorithms, especially their time complexity.
