Introduction to Recursion

What is Recursion?

Recursion is a programming technique in which a function calls itself to solve a problem.

Instead of solving the entire problem at once, the function breaks it into smaller versions of the same problem until it reaches a stopping condition.

Definition: A function that calls itself directly or indirectly is called a Recursive Function.

Real-Life Analogy

Example 1: Russian Dolls (Matryoshka)

Imagine opening a Russian doll.

Big Doll
   ↓
Medium Doll
   ↓
Small Doll
   ↓
Tiny Doll

Each doll contains another smaller doll.

Similarly, a recursive function keeps calling itself with a smaller problem until no smaller problem remains.

Example 2: Climbing Stairs

Suppose you want to climb 5 stairs.

"I need to climb 5 stairs."

Think:

↓

↓

↓

The problem becomes smaller with every recursive call.

Components of Recursion

Every recursive function has two essential parts.

1. Base Case

The condition where recursion stops.

Without a base case, the function keeps calling itself forever.

Example:

if(n == 0)
    return;

2. Recursive Case

The function calls itself with a smaller problem.

Example:

function(n - 1);

General Structure

returnType function(parameters)
{
    if(base_condition)
    {
        return value;
    }

    return function(smaller_problem);
}

Factorial Example

The factorial of a number is defined as:

5! = 5 × 4 × 3 × 2 × 1

= 120

Recursive definition:

n! = n × (n − 1)!

0! = 1

Recursive Program

#include <stdio.h>

int factorial(int n)
{
    if(n == 0)
        return 1;

    return n * factorial(n - 1);
}

int main()
{
    printf("%d", factorial(5));

    return 0;
}

Output

120

How Factorial Works

factorial(5)

↓

↓

5 × 4 × factorial(3)

↓

5 × 4 × 3 × factorial(2)

↓

5 × 4 × 3 × 2 × factorial(1)

↓

5 × 4 × 3 × 2 × 1 × factorial(0)

↓

1

What Happens Inside Memory?

Every recursive call is stored in a special memory area called the Call Stack.

Example:

factorial(3)

↓

factorial(2)

↓

factorial(1)

↓

factorial(0)

Call Stack:

┌──────────────┐
│ factorial(0) │
├──────────────┤
│ factorial(1) │
├──────────────┤
│ factorial(2) │
├──────────────┤
│ factorial(3) │
└──────────────┘

After the base case is reached, each function is removed from the stack in Last In, First Out (LIFO) order.

Advantages of Recursion

  • Code is shorter and easier to understand for many problems.
  • Naturally solves divide-and-conquer problems.
  • Useful for tree and graph traversals.
  • Simplifies problems like factorial, Fibonacci, and Tower of Hanoi.

Disadvantages of Recursion

  • Uses extra memory due to the call stack.
  • Can be slower than iteration because of function call overhead.
  • Missing a proper base case can lead to infinite recursion and Stack Overflow.

Common Mistakes

1. Missing Base Case

void fun()
{
    fun();
}

❌ Infinite recursion → Stack Overflow.

2. Base Case Never Reached

void fun(int n)
{
    if(n == 0)
        return;

    fun(n + 1);
}

❌ n keeps increasing, so n == 0 is never reached.

3. Wrong Recursive Call

factorial(n);

❌ The problem size never decreases.

Correct:

factorial(n - 1);

Key Points to Remember

  • A recursive function calls itself.
  • Every recursive function needs a base case.
  • The recursive call should work on a smaller problem.
  • Function calls are stored in the call stack.
  • Recursion is ideal for divide-and-conquer and hierarchical problems.
  • Without a proper base case, recursion results in infinite recursion and stack overflow.
