Tail Recursion

What is Tail Recursion?

Tail Recursion is a type of recursion in which the recursive function call is the last operation performed by the function.

After the recursive call, no computation remains.

Definition: A recursive function is called Tail Recursive if the recursive call is the final statement executed before the function returns.

General Structure

returnType function(parameters)
{
    if(base_condition)
        return;

    // Some work before recursion

    function(smaller_problem);

    // Nothing after recursive call
}

The important rule is:

Recursive Call

↓

Function Ends

There should be no statements after the recursive call.

Imagine walking down a staircase.

Once you move to the next step, you never return to perform extra work on the previous step.

Tail recursion behaves in the same way.

Example 1: Print Numbers (1 to 5)

#include <stdio.h>

void print(int n)
{
    if(n > 5)
        return;

    printf("%d ", n);

    print(n + 1);
}

int main()
{
    print(1);

    return 0;
}

Output

1 2 3 4 5

Why is it Tail Recursive?

printf("%d ", n);

print(n + 1);

The recursive call is the last statement.

Nothing is executed after:

print(n + 1);

Hence, this is Tail Recursion.

Example 2: Countdown

#include <stdio.h>

void countdown(int n)
{
    if(n == 0)
        return;

    printf("%d ", n);

    countdown(n - 1);
}

int main()
{
    countdown(5);

    return 0;
}

Output

5 4 3 2 1

Again, after:

countdown(n-1);

the function immediately returns.

Tail Recursive Factorial

The usual factorial function is not tail recursive because multiplication happens after the recursive call returns.

Normal factorial:

return n * factorial(n-1);

Here, after factorial(n-1) returns, multiplication is still pending.

We can rewrite it using an accumulator.

#include <stdio.h>

int factorialTail(int n, int result)
{
    if(n == 0)
        return result;

    return factorialTail(n - 1, result * n);
}

int main()
{
    printf("%d", factorialTail(5, 1));

    return 0;
}

Output

120

Dry Run

Call:

factorialTail(5,1)

Execution:

factorialTail(5,1)

↓

factorialTail(4,5)

↓

factorialTail(3,20)

↓

factorialTail(2,60)

↓

factorialTail(1,120)

↓

factorialTail(0,120)

The result is carried forward in the result parameter, so no multiplication is left after the recursive call.

Tail Call Optimization (TCO)

Some compilers can optimize tail-recursive functions.

Instead of keeping every recursive call on the call stack, they reuse the current stack frame.

Benefits:

  • Less memory usage.
  • Faster execution.
  • Prevents stack overflow for deep recursion.

Note: Standard C does not guarantee Tail Call Optimization. Some compilers (such as GCC or Clang with optimization enabled) may perform it automatically.

Tail Recursion vs Normal Recursion

Tail Recursion

void fun(int n)
{
    if(n == 0)
        return;

    printf("%d ", n);

    fun(n-1);
}

The recursive call is the last operation.

Not Tail Recursion

void fun(int n)
{
    if(n == 0)
        return;

    fun(n-1);

    printf("%d ", n);
}

The printf() executes after the recursive call returns, so this is Head Recursion, not Tail Recursion.

Tail Recursion vs Iteration

Tail recursion often has an equivalent iterative solution.

Tail Recursive Version:

void print(int n)
{
    if(n > 5)
        return;

    printf("%d ", n);

    print(n+1);
}

Iterative Version:

for(int i = 1; i <= 5; i++)
{
    printf("%d ", i);
}

Both produce:

1 2 3 4 5

Advantages

  • Simple and easy to understand.
  • Can be optimized by some compilers.
  • Requires no work after the recursive call.
  • Often convertible to loops.

Disadvantages

  • Still uses recursive calls if the compiler does not optimize.
  • Deep recursion may cause stack overflow.
  • Sometimes less intuitive than iteration.

Applications

  • Countdown timers.
  • Traversing linked lists recursively.
  • Recursive printing.
  • Tail-recursive mathematical computations.
  • Functional programming languages.

Key Points to Remember

  • In Tail Recursion, the recursive call is the last statement.
  • No computation remains after the recursive call.
  • Tail recursion can sometimes be optimized into iteration by the compiler.
  • A tail-recursive function is generally more memory-efficient than other recursive forms when optimization is available.
  • Not every recursive function can be naturally rewritten as tail recursive.
