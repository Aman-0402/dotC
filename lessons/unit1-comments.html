Single-Line (//) and Multi-Line (/* ... */) Comments

Comments are one of the simplest but most useful features in C programming.

They help programmers explain the code, making it easier to understand and maintain.

Comments are ignored by the compiler, so they do not affect the execution of the program.

What are Comments?

Definition

A Comment is a piece of text written inside a program to explain the code. It is not executed by the compiler.

Comments are useful for:

  • Explaining the purpose of the code.
  • Improving readability.
  • Helping other programmers understand the program.
  • Temporarily disabling code during testing.

Types of Comments in C

There are two types of comments:

  1. Single-Line Comments (//)
  2. Multi-Line Comments (/* ... */)

1. Single-Line Comments (//)

A Single-Line Comment starts with //.

Everything after // on that line is ignored by the compiler.

Syntax

// This is a single-line comment

Example 1

#include <stdio.h>

int main()
{
    // Print Hello World
    printf("Hello World");

    return 0;
}

Output

Hello World

The comment:

// Print Hello World

is ignored during compilation.

Example 2

int age = 20;   // Store student's age

Here, the comment explains what the variable stores.

2. Multi-Line Comments (/* ... */)

A Multi-Line Comment begins with /* and ends with */.

It can span multiple lines.

Syntax

/*
This is
a multi-line
comment
*/

Example

#include <stdio.h>

/*
This program
prints
Hello World
*/

int main()
{
    printf("Hello World");

    return 0;
}

Output

Hello World

Difference Between Single-Line and Multi-Line Comments

Feature Single-Line (//) Multi-Line (/* ... */)
Number of Lines One line One or more lines
Starts With // /*
Ends With End of line */
Best For Short explanations Detailed descriptions

Using Comments for Documentation

Comments can describe the program.

Example

/*
Program Name : Addition Program
Author       : Aman
Date         : 31 July 2026
Purpose      : Add two numbers
*/

This type of comment is usually written at the beginning of a program.

Using Comments to Explain Logic

#include <stdio.h>

int main()
{
    int a = 10;
    int b = 20;

    // Calculate the sum
    int sum = a + b;

    // Display the result
    printf("%d", sum);

    return 0;
}

Comments explain each important step.

Using Comments to Disable Code (Comment Out)

Sometimes programmers temporarily disable code for testing.

Example

#include <stdio.h>

int main()
{
    printf("Hello");

    // printf("World");

    return 0;
}

Output

Hello

The second printf() is ignored because it is commented out.

Multi-Line Comment Example

#include <stdio.h>

int main()
{
    /*
    printf("Hello");
    printf("World");
    */

    printf("C Programming");

    return 0;
}

Output

C Programming

Rules for Writing Comments

  • Use comments to explain why the code exists, not just what it does.
  • Keep comments short and meaningful.
  • Update comments if the code changes.
  • Avoid unnecessary comments.

Good vs Bad Comments

Good Comment

// Calculate total marks
total = m1 + m2 + m3;

The comment explains the purpose.

Bad Comment

// Add a and b
sum = a + b;

The code already makes this obvious, so the comment adds little value.

Common Mistakes

1. Forgetting to Close a Multi-Line Comment

Wrong

/*
This comment never ends

printf("Hello");

The compiler treats everything after /* as part of the comment, causing an error.

Correct

/*
This comment ends properly
*/

2. Nesting Multi-Line Comments

Wrong

/*
Outer comment

/*
Inner comment
*/

*/

C does not support nested multi-line comments.

3. Commenting Important Code Accidentally

// return 0;

This may cause unexpected behavior or compiler warnings in some cases.

Always check what you've commented out.

Advantages of Comments

  • Improve readability.
  • Help in debugging.
  • Make maintenance easier.
  • Explain complex logic.
  • Useful for teamwork.

Disadvantages of Poor Comments

  • Too many comments make code cluttered.
  • Outdated comments can mislead programmers.
  • Obvious comments reduce readability.

Real-Life Analogy

Imagine reading a textbook.

The main text explains the subject.

The notes in the margin help you understand important points.

Book Content
     │
     ▼
Program Code

Side Notes
     │
     ▼
Comments

The notes are for readers, not for the printer. Similarly, comments are for programmers, not for the compiler.

Complete Example

#include <stdio.h>

/*
Program: Addition of Two Numbers
Author : Aman
Purpose: Demonstrate comments
*/

int main()
{
    int a = 10;
    int b = 20;

    // Calculate sum
    int sum = a + b;

    // Display result
    printf("Sum = %d", sum);

    return 0;
}

Output

Sum = 30

Key Points to Remember

  • Comments are ignored by the compiler.
  • They improve code readability and documentation.
  • // is used for single-line comments.
  • /* ... */ is used for multi-line comments.
  • C does not support nested multi-line comments.
  • Good comments explain why something is done, not just what the code does.

Interview Questions

Q1. What is a comment in C?

Answer: A comment is text written in a program to explain the code. It is ignored by the compiler.

Q2. How many types of comments are there in C?

Answer: Two: Single-line (//) and Multi-line (/* ... */).

Q3. Can comments affect program execution?

Answer: No. The compiler ignores comments.

Q4. Can you nest multi-line comments in C?

Answer: No. Nested multi-line comments are not allowed.

Q5. Why are comments important?

Answer: They improve readability, help explain program logic, simplify debugging, and make code easier to maintain.
