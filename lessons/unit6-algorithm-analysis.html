Algorithm Analysis

Algorithm Analysis is the process of evaluating the efficiency of an algorithm by measuring the resources it requires, mainly:

  • Execution Time (Time Complexity)
  • Memory Usage (Space Complexity)

It helps us determine which algorithm performs better for a given problem, especially when the input size becomes very large.

1. Introduction to Data Structures & Algorithms (DSA)

What is a Data Structure?

A Data Structure is a way of organizing and storing data so that it can be accessed and modified efficiently.

Examples

Data Structure Usage
ArrayStore multiple values of same type
Linked ListDynamic memory storage
StackLIFO operations
QueueFIFO operations
TreeHierarchical data
GraphNetworks and maps
Hash TableFast searching

What is an Algorithm?

An Algorithm is a step-by-step procedure to solve a problem or perform a specific task.

It is like a recipe that tells the computer exactly what to do.

Example

Problem: Add two numbers.

Algorithm:

Step 1: Start

Step 2: Read A and B

Step 3: Sum = A + B

Step 4: Print Sum

Step 5: Stop

Relationship between Data Structure and Algorithm

  • Data Structure stores data.
  • Algorithm processes data.

Example:

Array → Binary Search

Stack → Expression Evaluation

Queue → CPU Scheduling

Tree → Searching

Why Study DSA?

  • Improves problem-solving skills
  • Helps write faster programs
  • Reduces memory usage
  • Essential for software development
  • Important for coding interviews

2. Characteristics of an Algorithm

A good algorithm must satisfy the following characteristics.

1. Input

An algorithm should accept zero or more inputs.

Example:

Enter two numbers
5 10

Input = 5 and 10

2. Output

An algorithm should produce at least one output.

Example

Input

5 10

Output

15

3. Definiteness

Every step should be clear and unambiguous.

Correct

Multiply A and B

Incorrect

Do something with A

4. Finiteness

Algorithm must terminate after a finite number of steps.

Correct

Repeat 10 times

Incorrect

Repeat forever

5. Effectiveness

Every instruction should be simple and executable.

Example

A = A + 1

This can be performed easily.

6. Correctness

Algorithm should produce the correct output for every valid input.

Example

Input:
4 5

Output:
9

7. Generality

Algorithm should solve all valid cases, not just one example.

Correct

Add any two numbers

Incorrect

Add only 5 and 10

Example Algorithm

Find Maximum of Two Numbers

Start

Read A and B

If A > B
    Print A
Else
    Print B

Stop

3. Time Complexity

Definition

Time Complexity measures how the running time of an algorithm grows as the input size (n) increases.

It does not measure the actual time in seconds. Instead, it counts how the number of operations increases with input size.

Why Time Complexity?

Suppose there are two programs:

Program A

100 operations

Program B

10,000 operations

For small input, both may seem fast.

For very large input:

  • Program A finishes quickly.
  • Program B becomes much slower.

Time complexity helps compare algorithms independent of hardware or programming language.

Common Time Complexities

Complexity Name Performance
O(1)ConstantExcellent
O(log n)LogarithmicExcellent
O(n)LinearGood
O(n log n)LinearithmicGood
O(n²)QuadraticSlow
O(n³)CubicVery Slow
O(2ⁿ)ExponentialExtremely Slow
O(n!)FactorialWorst

Example 1: Constant Time — O(1)

int x = arr[5];

Only one operation.

Regardless of array size:

  • 10 elements
  • 1000 elements
  • 1 million elements

Execution time remains approximately the same.

Time Complexity: O(1)

Example 2: Linear Time — O(n)

for(int i=0;i<n;i++)
{
    printf("%d ",arr[i]);
}

If:

n = 5 → 5 operations

n = 100 → 100 operations

n = 1000 → 1000 operations

Time Complexity: O(n)

Example 3: Quadratic Time — O(n²)

for(int i=0;i<n;i++)
{
    for(int j=0;j<n;j++)
    {
        printf("*");
    }
}

Operations:

n × n = n²

If n = 100

Operations = 10,000

Time Complexity: O(n²)

4. Space Complexity

Definition

Space Complexity measures the total amount of memory an algorithm requires during execution.

It includes:

  • Input storage
  • Variables
  • Auxiliary (extra) memory
  • Function call stack (if applicable)

Formula

Space Complexity =
Input Space + Auxiliary Space

Example 1

int a;

Uses one integer variable.

Space Complexity:

O(1)

Example 2

int arr[n];

Memory depends on n.

Space Complexity:

O(n)

Example 3

int matrix[n][n];

Memory required:

n × n

Space Complexity:

O(n²)

Example 4 (Recursive Function)

void fun(int n)
{
    if(n==0)
        return;

    fun(n-1);
}

Each recursive call uses stack memory.

Space Complexity:

O(n)

Difference Between Time Complexity and Space Complexity

Time Complexity Space Complexity
Measures execution timeMeasures memory usage
Counts operationsCounts memory consumed
Faster algorithms are preferredLower memory usage is preferred
Example: O(n)Example: O(n)

5. Asymptotic Notations

Definition

Asymptotic Notations describe the growth rate of an algorithm as the input size (n) becomes very large.

They ignore:

  • Machine speed
  • Programming language
  • Compiler optimization
  • Constant factors

Instead, they focus on how performance scales with increasing input size.

Types of Asymptotic Notations

  1. Big O (O) – Upper Bound (Worst Case)
  2. Big Omega (Ω) – Lower Bound (Best Case)
  3. Big Theta (Θ) – Tight Bound (Average/Exact Growth)

6. Big O Notation (O)

Definition

Big O represents the maximum time an algorithm can take for an input of size n.

It describes the worst-case performance.

Example

Linear Search (searching the last element):

for(int i=0;i<n;i++)
{
    if(arr[i]==key)
        return i;
}

If the key is at the last position or absent, all n elements are checked.

Time Complexity: O(n)

Common Big O Examples

Algorithm Big O
Array Index AccessO(1)
Linear SearchO(n)
Binary SearchO(log n)
Bubble SortO(n²)
Merge SortO(n log n)

7. Big Omega (Ω)

Definition

Big Omega (Ω) represents the minimum time an algorithm takes.

It describes the best-case performance.

Example

Linear Search:

for(int i=0;i<n;i++)
{
    if(arr[i]==key)
        return i;
}

If the key is the first element, only one comparison is made.

Time Complexity: Ω(1)

Example

Searching for 10:

10 20 30 40 50

Key = 10

Only one comparison is needed.

Best Case: Ω(1)

8. Big Theta (Θ)

Definition

Big Theta (Θ) represents the tight bound of an algorithm.

It describes the situation where the algorithm's running time grows at the same rate in both upper and lower bounds.

In simple terms, it represents the average or exact growth rate.

Example

Printing every array element:

for(int i=0;i<n;i++)
{
    printf("%d ",arr[i]);
}

The loop always executes exactly n times.

Best Case = n

Worst Case = n

Therefore:

Θ(n)

Comparison of Asymptotic Notations

Notation Meaning Case
Big O (O)Upper BoundWorst Case
Big Omega (Ω)Lower BoundBest Case
Big Theta (Θ)Tight BoundAverage/Exact Growth

Real-Life Example: Searching a Book in a Library

Imagine you're looking for a book on a shelf containing n books:

  • Best Case (Ω(1)): The book is the first one you check.
  • Worst Case (O(n)): The book is the last one or not present.
  • Average/Typical Case (Θ(n)): On average, you check about half the books, which still grows linearly with n.

Key Points to Remember

  • Data Structure organizes data; an Algorithm processes data.
  • A good algorithm should have Input, Output, Definiteness, Finiteness, Effectiveness, Correctness, and Generality.
  • Time Complexity measures how execution time grows with input size.
  • Space Complexity measures how memory usage grows with input size.
  • Big O (O) represents the Worst Case.
  • Big Omega (Ω) represents the Best Case.
  • Big Theta (Θ) represents the Tight/Average Growth.
  • Preferred time complexities are O(1), O(log n), and O(n), while O(n²) and beyond become inefficient for large inputs.
