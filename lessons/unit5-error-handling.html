Error Handling

Error handling is the process of detecting, reporting, and responding to errors that occur while a program is running.

Errors can happen due to invalid input, missing files, insufficient memory, division by zero, hardware failures, or operating system issues. Proper error handling helps prevent program crashes and makes applications more reliable.

What is Error Handling?

Error handling is a mechanism used to identify errors and take appropriate action instead of allowing the program to terminate unexpectedly.

Why Error Handling?

  • Prevents unexpected crashes
  • Helps identify the cause of errors
  • Improves program reliability
  • Makes debugging easier
  • Provides user-friendly error messages

1. exit()

Definition

The exit() function immediately terminates the program and returns a status code to the operating system.

It is declared in the <stdlib.h> header file.

Syntax

#include <stdlib.h>

exit(status);

Exit Status Codes

Status Meaning
0Successful termination
EXIT_SUCCESSSuccessful termination
1Abnormal termination
EXIT_FAILUREProgram terminated due to an error

Example 1

#include <stdio.h>
#include <stdlib.h>

int main()
{
    printf("Program Started\n");

    exit(0);

    printf("This line will never execute.");

    return 0;
}

Output

Program Started

The second printf() is never executed because exit() terminates the program immediately.

Example 2

#include <stdio.h>
#include <stdlib.h>

int main()
{
    FILE *fp;

    fp = fopen("student.txt", "r");

    if(fp == NULL)
    {
        printf("Cannot Open File\n");
        exit(EXIT_FAILURE);
    }

    printf("File Opened Successfully");

    fclose(fp);

    return 0;
}

Advantages of exit()

  • Terminates the program safely
  • Returns an exit status to the operating system
  • Useful for handling fatal errors
  • Prevents execution of invalid code

2. perror()

Definition

The perror() function prints a custom message followed by the system-generated error description for the most recent error.

It is declared in <stdio.h>.

Syntax

perror("Message");

Example

#include <stdio.h>

int main()
{
    FILE *fp;

    fp = fopen("abc.txt", "r");

    if(fp == NULL)
    {
        perror("Error");
    }

    return 0;
}

Possible Output

Error: No such file or directory

Here:

  • Error → Custom message
  • No such file or directory → System-generated error message

Another Example

#include <stdio.h>

int main()
{
    FILE *fp;

    fp = fopen("data.txt", "r");

    if(fp == NULL)
    {
        perror("Unable to Open File");
    }

    return 0;
}

Possible Output

Unable to Open File: No such file or directory

Advantages of perror()

  • Displays meaningful error messages
  • Easy to debug programs
  • Uses operating system error information
  • Saves time compared to writing custom messages

3. <errno.h>

Definition

The <errno.h> header file provides access to the global variable errno, which stores an error number whenever a library function fails.

Note: The correct header is <errno.h>, not error.h.

Syntax

#include <errno.h>

The errno Variable

  • Set automatically when an error occurs
  • Contains a numeric error code
  • Can be used with perror() or strerror()

Example

#include <stdio.h>
#include <errno.h>

int main()
{
    FILE *fp;

    fp = fopen("sample.txt", "r");

    if(fp == NULL)
    {
        printf("Error Number : %d\n", errno);
    }

    return 0;
}

Possible Output

Error Number : 2

(Error number may vary depending on the operating system.)

Using strerror()

The strerror() function converts an error number into a human-readable message.

Header files:

#include <string.h>
#include <errno.h>

Example

#include <stdio.h>
#include <string.h>
#include <errno.h>

int main()
{
    FILE *fp;

    fp = fopen("sample.txt", "r");

    if(fp == NULL)
    {
        printf("Error %d : %s\n", errno, strerror(errno));
    }

    return 0;
}

Possible Output

Error 2 : No such file or directory

Complete Example

#include <stdio.h>
#include <stdlib.h>
#include <errno.h>

int main()
{
    FILE *fp;

    fp = fopen("student.txt", "r");

    if(fp == NULL)
    {
        perror("File Error");
        exit(EXIT_FAILURE);
    }

    printf("File Opened Successfully\n");

    fclose(fp);

    return 0;
}

Possible Output (if file does not exist)

File Error: No such file or directory

Best Practices

  • Always check the return value of functions like fopen(), malloc(), and fread().
  • Use perror() to display meaningful system error messages.
  • Use exit(EXIT_FAILURE) for unrecoverable errors.
  • Include <errno.h> when working with errno.
  • Close any opened files before terminating the program.

Key Takeaways

  • Error handling helps programs detect and respond to runtime problems gracefully.
  • exit() terminates the program immediately and returns a status code to the operating system.
  • perror() prints a custom message along with the system-generated description of the last error.
  • errno (defined in <errno.h>) stores an error code whenever a library function fails.
  • strerror() converts the numeric value of errno into a readable error message.
  • Always validate the return values of file and memory operations to write robust and reliable C programs.
