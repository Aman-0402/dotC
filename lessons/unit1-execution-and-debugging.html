Execution and Debugging

Writing a program is only half the job. The other half is running it correctly and fixing errors.

This process involves two important concepts:

  1. Execution – Running the program.
  2. Debugging – Finding and fixing errors.

What is Program Execution?

Execution is the process of running a compiled program so that the CPU performs the instructions written in the program.

Once a C program is compiled and linked successfully, an executable file is created.

When you run that executable, the operating system loads it into memory (RAM), and the CPU starts executing instructions from the main() function.

What is Debugging?

Debugging is the process of identifying, locating, and fixing errors (bugs) in a program.

A programmer spends a significant amount of time debugging programs.

What is a Bug?

A Bug is any mistake or error in a program that causes incorrect behavior.

Examples:

  • Program does not compile.
  • Program crashes.
  • Wrong output.
  • Infinite loop.
  • Unexpected results.

Types of Errors in C

There are three major types of errors:

  1. Syntax Errors
  2. Runtime Errors
  3. Logical Errors

1. Syntax Error

Definition

A Syntax Error occurs when the programmer violates the rules (syntax) of the C language.

The compiler detects these errors during compilation.

Example 1: Missing Semicolon

#include <stdio.h>

int main()
{
    printf("Hello")

    return 0;
}

Compiler Error

error: expected ';'

Correct Code

printf("Hello");

Example 2: Missing Braces

Wrong

int main()

printf("Hello");

Correct

int main()
{
    printf("Hello");
}

Example 3: Wrong Function Name

Wrong

Printf("Hello");

Correct

printf("Hello");

Remember:

C is case-sensitive.

Common Syntax Errors

  • Missing semicolon (;)
  • Missing braces ({})
  • Missing quotation marks (" ")
  • Misspelled keywords
  • Missing header files
  • Unmatched parentheses

2. Runtime Error

Definition

A Runtime Error occurs while the program is running, even though it compiled successfully.

Example 1: Division by Zero

#include <stdio.h>

int main()
{
    int a = 10;
    int b = 0;

    printf("%d", a / b);

    return 0;
}

Result

Program crashes

Example 2: Invalid Memory Access

int *ptr = NULL;

printf("%d", *ptr);

Result

Segmentation Fault

We'll learn pointers later, but this shows a common runtime error.

Example 3: File Not Found

Trying to open a file that doesn't exist may also cause a runtime error.

Common Runtime Errors

  • Division by zero
  • Invalid memory access
  • Array index out of bounds (undefined behavior in C)
  • File opening failure
  • Stack overflow (deep recursion)

3. Logical Error

Definition

A Logical Error occurs when the program compiles and runs successfully, but produces the wrong output.

These are the hardest errors to detect because the compiler cannot identify them.

Example

Problem:

Find the sum of two numbers.

Wrong Code

#include <stdio.h>

int main()
{
    int a = 10;
    int b = 20;

    printf("%d", a * b);

    return 0;
}

Output

200

Expected Output

30

The program compiled successfully but the logic is incorrect.

Correct Code

printf("%d", a + b);

Comparison of Errors

Error Type Detected By When It Occurs Example
Syntax Error Compiler Before execution Missing ;
Runtime Error Operating System / Runtime During execution Division by zero
Logical Error Programmer After execution Wrong formula

What is a Debugger?

A Debugger is a software tool that helps programmers find and fix errors.

Popular IDEs such as Visual Studio Code, Code::Blocks, Visual Studio, and CLion provide debugging features.

Common Debugging Techniques

1. Read Error Messages

Example:

error: expected ';'

The compiler usually tells you the line number where it found the problem.

2. Use printf() for Debugging

Example

#include <stdio.h>

int main()
{
    int a = 5;
    int b = 10;

    printf("a = %d\n", a);
    printf("b = %d\n", b);

    printf("%d", a + b);

    return 0;
}

Output

a = 5
b = 10
15

Printing variable values is one of the simplest ways to understand what the program is doing.

3. Execute Step by Step

Most debuggers allow you to:

  • Run one line at a time.
  • Check variable values.
  • Pause execution.
  • Continue execution.

This helps locate exactly where an error occurs.

Best Practices to Avoid Errors

  • Write small programs first.
  • Compile frequently.
  • Read compiler error messages carefully.
  • Use meaningful variable names.
  • Test with different inputs.
  • Keep code properly indented.
  • Add comments where necessary.

Real-Life Analogy

Imagine you're solving a math problem.

  • Syntax Error: You forgot to write a number or symbol.
  • Runtime Error: Your calculator stops working halfway through.
  • Logical Error: You solved the problem using the wrong formula.

Key Points to Remember

  • Execution is the process of running a compiled program.
  • Debugging means finding and fixing errors.
  • A Bug is any mistake in a program.
  • Syntax Errors are detected by the compiler.
  • Runtime Errors occur during execution.
  • Logical Errors produce incorrect output and are found by testing.
  • Reading compiler messages and using printf() are simple but effective debugging techniques.

Interview Questions

Q1. What is debugging?

Answer: Debugging is the process of finding and fixing errors (bugs) in a program.

Q2. What is the difference between execution and debugging?

Answer: Execution is running the program, while debugging is identifying and correcting errors.

Q3. Which type of error is detected by the compiler?

Answer: Syntax errors.

Q4. Which error is the hardest to detect?

Answer: Logical errors, because the program compiles and runs but gives incorrect results.

Q5. What is a debugger?

Answer: A debugger is a tool that helps programmers execute code step by step, inspect variables, and identify errors.
