Source Code, Object Code & Executable Code

In the previous topic, we saw that a C program goes through several stages before it runs.

Now, let's understand the three most important files created during this process:

  1. Source Code
  2. Object Code
  3. Executable Code

These are frequently asked in college exams and technical interviews.

1. Source Code

Definition

Source Code is the program written by the programmer using a programming language such as C.

It is human-readable and can be edited.

Example

#include <stdio.h>

int main()
{
    printf("Hello, World!");

    return 0;
}

Suppose you save this program as:

hello.c

Here,

  • hello → File name
  • .c → Extension for C source code

Characteristics

  • Written by the programmer.
  • Easy to read and modify.
  • Cannot be executed directly.
  • Must be compiled first.

Real-Life Analogy

Imagine writing a letter.

Letter Written
      │
      ▼
Source Code

The letter is understandable by humans, but not by the computer.

2. Object Code

After successful compilation and assembly, the program becomes Object Code.

Definition

Object Code is the machine code generated by the assembler after converting assembly language.

It contains machine instructions but is not yet a complete program.

Why can't it run directly?

Because it may still need external library functions.

Example:

printf("Hello");

Your object file only contains a reference to printf().

The actual implementation of printf() exists in the C Standard Library.

The Linker combines them later.

Extension

Linux

hello.o

Windows

hello.obj

Characteristics

  • Machine-readable.
  • Not human-readable.
  • Cannot execute directly.
  • Needs the linker.

Analogy

Imagine building a bicycle.

You have:

  • Frame
  • Wheels
  • Seat

But they're not assembled.

That's like Object Code—important parts exist, but the final product isn't ready yet.

3. Executable Code

After linking, the final program is created.

Definition

Executable Code is the final machine code that the operating system can execute.

Extension

Windows

hello.exe

Linux

a.out

(or a custom executable name if specified)

Characteristics

  • Fully linked.
  • Ready to run.
  • Contains all required library references.
  • Executed by the operating system.

Example in GCC

Suppose your program is saved as:

hello.c

Compile only

gcc -c hello.c

Output:

hello.o

Here, -c tells GCC to compile and assemble only, without linking.

Create Executable

gcc hello.c

Linux output:

a.out

Or with a custom name:

gcc hello.c -o hello

Output:

hello

On Windows (MinGW):

hello.exe

Frequently Asked Exam Question

Q. Why can't Object Code run directly?

Answer:

Because it may contain references to external libraries (such as printf(), scanf(), sqrt(), etc.). The Linker must combine these libraries with the object code before an executable program is created.

Common Misconceptions

❌ Object Code and Executable Code are the same.

Incorrect.

Object Code is incomplete and still needs linking.

❌ Source Code can be executed directly.

Incorrect.

Source Code must first be compiled and linked.

❌ Executable Code can be edited like Source Code.

Incorrect.

Executable files are machine code and are not intended to be edited.

Key Points to Remember

  • Source Code is written by the programmer and stored in a .c file.
  • Object Code is generated by the assembler and stored in a .o or .obj file.
  • Executable Code is created by the linker and can be executed by the operating system.
  • Source Code is human-readable.
  • Object Code and Executable Code are machine-readable.
  • Only Executable Code can be run directly.

Interview Questions

Q1. What is Source Code?

Answer: The C program written by the programmer in a .c file.

Q2. What is Object Code?

Answer: Machine code generated after assembly that is not yet executable because it still needs linking.

Q3. What is Executable Code?

Answer: The final machine code produced after linking, which can be executed by the operating system.

Q4. Why is Object Code not executable?

Answer: Because it may still contain unresolved references to external library functions, which are resolved by the linker.

Q5. Which file can the operating system execute directly?

Answer: The Executable File (.exe on Windows or a.out/custom executable on Linux).
