Linkers and Loaders

After a C program is compiled, it still cannot run immediately.

Two important system programs work behind the scenes:

  1. Linker
  2. Loader

These are essential parts of the program execution process and are frequently asked in interviews.

What is a Linker?

Definition

A Linker is a system program that combines one or more object files and required library files to create a single executable program.

Simply put,

The Linker joins everything needed to build the final executable file.

Why Do We Need a Linker?

Consider the following program:

#include <stdio.h>

int main()
{
    printf("Hello World");

    return 0;
}

The function

printf()

is not written inside your program.

It already exists in the C Standard Library.

The compiler knows that printf() exists but doesn't include its implementation.

The Linker finds the required library code and combines it with your object code.

Example

Suppose your program contains:

printf("Hello");

The linker searches the C Standard Library for the implementation of printf() and adds it to the executable.

Without the linker, the executable cannot be created.

Static Linking

In Static Linking, all required library code is copied into the executable file.

Program
      │
      ▼
Library Functions
      │
Copied into
      │
Executable

Advantages

  • Program runs independently.
  • No need for external libraries at runtime.
  • Easy to distribute.

Disadvantages

  • Larger executable size.
  • Library updates require recompilation.

Dynamic Linking

In Dynamic Linking, the executable stores only references to shared libraries.

The actual library is loaded when the program starts.

Executable
      │
      ▼
Reference to Library
      │
      ▼
Library Loaded at Runtime

Advantages

  • Smaller executable size.
  • Shared libraries save memory.
  • Easy to update libraries.

Disadvantages

  • Program depends on external library files.
  • Missing libraries can prevent the program from running.

What is a Loader?

Definition

A Loader is a system program that loads the executable file into RAM (Main Memory) and prepares it for execution.

After the linker creates the executable, the loader takes over.

The Loader ensures the program is placed into memory correctly before execution begins.

What Does the Loader Do?

The loader performs several tasks:

  • Loads the executable into RAM.
  • Allocates memory for the program.
  • Loads required shared libraries (for dynamic linking).
  • Sets up the program's execution environment.
  • Transfers control to the main() function.

Example Using GCC

Suppose you have:

hello.c

Compile Only

gcc -c hello.c

Output:

hello.o

Compile + Link

gcc hello.c -o hello

Output:

hello

Here:

  • Compiler converts source code to object code.
  • Linker creates the executable named hello.

Run the Program

Linux/macOS:

./hello

Windows:

hello.exe

At this stage, the Loader loads the program into RAM, and execution begins.

Common Interview Question

Q. What happens if the linker cannot find a required function?

Example:

printf("Hello");

If the required library is missing or not linked properly, the linker generates a linker error, such as:

undefined reference to 'printf'

No executable file is created.

Key Points to Remember

  • The Linker combines object files and required libraries to create an executable program.
  • The Loader loads the executable into RAM and prepares it for execution.
  • Static Linking copies libraries into the executable.
  • Dynamic Linking loads libraries at runtime.
  • Execution starts from the main() function after the loader finishes its work.

Interview Questions

Q1. What is a Linker?

Answer: A Linker is a system program that combines object files and required libraries to create an executable program.

Q2. What is a Loader?

Answer: A Loader is a system program that loads the executable into RAM and prepares it for execution.

Q3. What is the difference between Static and Dynamic Linking?

Answer: Static linking copies library code into the executable, while dynamic linking loads shared libraries at runtime.

Q4. Which comes first: Linker or Loader?

Answer: The Linker runs first to create the executable. The Loader runs afterward when the executable is started.

Q5. Does the Linker execute the program?

Answer: No. The Linker only creates the executable. The Loader loads it into memory, and then the CPU executes it.
