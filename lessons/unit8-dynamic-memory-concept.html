Dynamic Memory Concept

Dynamic memory allocation is the foundation of linked lists. Without it, linked lists cannot exist.

Why Do We Need Dynamic Memory?

Before learning linked lists, let's understand a problem.

Suppose you create an array:

int arr[5];

Memory is allocated like this:

+----+----+----+----+----+
| 10 | 20 | 30 | 40 | 50 |
+----+----+----+----+----+

Problems:

  • Size is fixed.
  • Cannot increase or decrease at runtime.
  • Memory is allocated before execution.

If later you want to store one more element:

10 20 30 40 50 60

The array cannot grow.

Static Memory Allocation

Memory allocated before program execution is called Static Memory Allocation.

Example:

int arr[100];

Characteristics:

  • Fixed size
  • Fast access
  • Cannot expand
  • May waste memory

Dynamic Memory Allocation

Memory allocated during program execution (runtime) is called Dynamic Memory Allocation.

The programmer requests memory whenever required.

Example:

int *ptr;

ptr = (int *)malloc(sizeof(int));

Memory is created only when malloc() is executed.

Where Does Dynamic Memory Come From?

A C program uses different memory areas:

+----------------------+
|      Code Segment    |
+----------------------+
|   Global Variables   |
+----------------------+
|        Heap          |  <-- Dynamic Memory
+----------------------+
|                      |
|                      |
+----------------------+
|        Stack         |
+----------------------+

Heap

  • Used for dynamic memory allocation.
  • Controlled by the programmer.
  • Memory remains allocated until it is explicitly released using free().

Stack

Stores:

  • Local variables
  • Function calls
  • Parameters

Memory is automatically released when the function ends.

Why Linked Lists Use Heap Memory

Consider this declaration:

struct Node *head;

Only the pointer head exists.

No node has been created yet.

head
 ↓
NULL

When you create a node:

head = (struct Node *)malloc(sizeof(struct Node));

A new node is allocated in the heap.

Heap

+-----------+
| Data | *  |
+-----------+

head
 ↓
+-----------+
| Data | *  |
+-----------+

Now the linked list has one node.

Memory Allocation Functions

1. malloc()

Syntax

pointer = (type *)malloc(size);

Example:

int *ptr;

ptr = (int *)malloc(sizeof(int));

Output:

Heap

+------+
|  ?   |
+------+

The allocated memory contains garbage values until initialized.

2. calloc()

Allocates memory and initializes all bytes to zero.

Syntax

pointer = (type *)calloc(n, size);

Example:

int *ptr;

ptr = (int *)calloc(5, sizeof(int));

Memory:

0 0 0 0 0

Difference Between malloc() and calloc()

Feature malloc() calloc()
InitializationGarbage valuesZero initialized
Parameters12
SpeedSlightly fasterSlightly slower

3. realloc()

Changes the size of previously allocated memory.

Example:

ptr = (int *)realloc(ptr, 10 * sizeof(int));

If possible:

  • Memory is expanded.
  • Otherwise, a new block is allocated, data is copied, and the old block is released.

4. free()

Releases dynamically allocated memory.

Example:

free(ptr);

After freeing:

Memory returned to Heap

It is good practice to write:

ptr = NULL;

This prevents dangling pointers (pointers that refer to freed memory).

Creating the First Linked List Node

Structure

struct Node
{
    int data;
    struct Node *next;
};

This structure defines a node with:

  • data → stores the value
  • next → stores the address of the next node

Creating a Node

struct Node *head;

head = (struct Node *)malloc(sizeof(struct Node));

Memory:

head
 ↓
+-----------+
| data | *  |
+-----------+

Assign Values

head->data = 10;
head->next = NULL;

Memory:

head
 ↓
+-----------+
| 10 | NULL |
+-----------+

This is the smallest valid linked list.

Creating Two Nodes

struct Node *first, *second;

first = (struct Node *)malloc(sizeof(struct Node));
second = (struct Node *)malloc(sizeof(struct Node));

first->data = 10;
first->next = second;

second->data = 20;
second->next = NULL;

Memory:

first
  ↓
+-----------+      +-----------+
| 10 |   ----|----->| 20 | NULL |
+-----------+      +-----------+

Why sizeof(struct Node)?

Suppose the structure is:

struct Node
{
    int data;
    struct Node *next;
};

sizeof(struct Node) automatically calculates the required memory for the entire node, including any padding added by the compiler. This makes the code portable and avoids hardcoding sizes.

Common Mistakes

Forgetting to Allocate Memory

❌ Wrong

struct Node *head;

head->data = 10;

head doesn't point to valid memory, leading to undefined behavior.

✔ Correct

head = (struct Node *)malloc(sizeof(struct Node));

head->data = 10;

Forgetting to Free Memory

malloc(...)

without

free(...)

causes a memory leak, where allocated memory remains unavailable until the program terminates.

Using Memory After free()

❌ Wrong

free(head);

head->data = 50;

This accesses freed memory and results in undefined behavior.

✔ Better

free(head);
head = NULL;

Real-Life Analogy

Imagine a hotel:

  • Stack → Rooms booked automatically for a short stay. Guests check out automatically.
  • Heap → Rooms booked manually. The guest stays until someone explicitly checks them out.

Linked list nodes are like heap rooms—they remain available until you call free().

Key Takeaways

  • Dynamic memory is allocated at runtime from the heap.
  • Linked lists rely on dynamic memory because their size changes during execution.
  • malloc() allocates uninitialized memory.
  • calloc() allocates zero-initialized memory.
  • realloc() resizes previously allocated memory.
  • free() releases memory back to the heap.
  • Every linked list node is created dynamically using malloc() and should eventually be released using free().
