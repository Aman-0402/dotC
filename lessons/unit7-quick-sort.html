Quick Sort

Quick Sort is one of the fastest and most widely used sorting algorithms. It is a comparison-based sorting algorithm that uses the Divide and Conquer technique.

Unlike Merge Sort, Quick Sort does not divide the array into equal halves. Instead, it selects a Pivot element and rearranges the array so that:

  • All elements smaller than the pivot are placed on the left.
  • All elements greater than the pivot are placed on the right.
  • The pivot reaches its correct sorted position.

The same process is then applied recursively to the left and right subarrays.

Real-Life Analogy

Imagine arranging students by height around a chosen student (the pivot).

Suppose the pivot student is 170 cm tall.

  • Students shorter than 170 cm stand on the left.
  • Students taller than 170 cm stand on the right.
  • The pivot remains in the middle.

Now repeat the same process separately for the left and right groups until everyone is in order.

Key Terminology

Pivot

A Pivot is the element chosen to partition the array.

The pivot can be:

  • First element
  • Last element
  • Middle element
  • Random element
  • Median of three (advanced optimization)

In this chapter, we will use the last element as the pivot (Lomuto Partition Scheme) because it is simple and commonly taught.

How Quick Sort Works

Given the array:

10 80 30 90 40 50 70

Step 1: Choose Pivot

Choose the last element.

10 80 30 90 40 50 [70]

Pivot = 70

Step 2: Partition

Move all elements smaller than 70 to the left and larger ones to the right.

10 30 40 50 70 90 80

Now 70 is in its correct sorted position.

Step 3: Recursively Sort Left

Left subarray:

10 30 40 50

Choose pivot = 50

Already partitioned.

Step 4: Recursively Sort Right

Right subarray:

90 80

Choose pivot = 80

Partition:

80 90

Final Sorted Array

10 30 40 50 70 80 90

Quick Sort Algorithm

QuickSort(low, high)

If low < high

    Partition array

    Pivot reaches correct position

    QuickSort(left)

    QuickSort(right)

Partition Algorithm (Lomuto)

Choose last element as Pivot

Maintain index i

Traverse array

If current element < Pivot

    Increment i

    Swap

Finally

Swap Pivot with i+1

Return Pivot Index

C Program

#include <stdio.h>

void swap(int *a, int *b)
{
    int temp = *a;
    *a = *b;
    *b = temp;
}

int partition(int arr[], int low, int high)
{
    int pivot = arr[high];
    int i = low - 1;

    for (int j = low; j < high; j++)
    {
        if (arr[j] < pivot)
        {
            i++;
            swap(&arr[i], &arr[j]);
        }
    }

    swap(&arr[i + 1], &arr[high]);

    return i + 1;
}

void quickSort(int arr[], int low, int high)
{
    if (low < high)
    {
        int pi = partition(arr, low, high);

        quickSort(arr, low, pi - 1);

        quickSort(arr, pi + 1, high);
    }
}

int main()
{
    int arr[] = {10, 80, 30, 90, 40, 50, 70};

    int n = sizeof(arr) / sizeof(arr[0]);

    quickSort(arr, 0, n - 1);

    printf("Sorted Array:\n");

    for (int i = 0; i < n; i++)
        printf("%d ", arr[i]);

    return 0;
}

Output

Sorted Array:
10 30 40 50 70 80 90

Code Explanation

Pivot Selection

int pivot = arr[high];

The last element is selected as the pivot.

Partition

for(int j = low; j < high; j++)

Traverse the array and move elements smaller than the pivot to the left.

Swap

swap(&arr[i], &arr[j]);

Places smaller elements before the pivot.

Final Pivot Placement

swap(&arr[i + 1], &arr[high]);

Moves the pivot to its correct sorted position.

Recursive Calls

quickSort(arr, low, pi - 1);

quickSort(arr, pi + 1, high);

Recursively sort the left and right partitions.

Time Complexity

Case Complexity
Best CaseO(n log n)
Average CaseO(n log n)
Worst CaseO(n²)

Why is the Worst Case O(n²)?

If the pivot is always the smallest or largest element (for example, when the array is already sorted and the last element is always chosen as the pivot), the partitions become highly unbalanced.

Example:

1 2 3 4 5

Pivot = 5

Left side has 4 elements, right side has 0 elements.

This continues recursively, leading to O(n²) time.

Space Complexity

Case Complexity
AverageO(log n)
WorstO(n)

The extra space is due to the recursive function call stack.

Advantages

  • Very fast in practice.
  • Average time complexity is O(n log n).
  • In-place sorting algorithm.
  • Requires very little extra memory.
  • Widely used in standard libraries and real-world applications.

Disadvantages

  • Worst-case time complexity is O(n²).
  • Not a stable sorting algorithm.
  • Recursive calls can become deep in the worst case.

Applications

  • Large in-memory datasets.
  • Standard library sorting functions.
  • Database systems.
  • Operating systems.
  • Competitive programming.
  • Real-time applications requiring fast average performance.

Key Points to Remember

  • Uses the Divide and Conquer technique.
  • Selects a pivot and partitions the array.
  • Elements smaller than the pivot move to the left.
  • Elements larger than the pivot move to the right.
  • In-place sorting algorithm.
  • Not stable.
  • Average Time Complexity: O(n log n).
  • Worst Time Complexity: O(n²).
